## 2026-07-19 - Extreme Process Fork Optimization in Bash Auditing Tool
**Learning:** Repetitive external process calls (like `ps -ef`, `grep`, `awk`) inside shell scripts to parse command-line arguments of a target daemon introduce massive CPU/process fork overhead. By caching the output of a single `ps` command into a variable once at startup and parsing the arguments using Bash's built-in regular expression matching (`[[ $VAR =~ REGEX ]]`) and substring matching (`[[ $VAR == *pattern* ]]`), process forks can be reduced by over 95%. Additionally, command substitution inside double quotes like `"$(show apid)"` executes correctly, whereas escaping backticks as `"\`show apid\`"` inside double quotes prints literal backticks, preventing shell evaluation.
**Action:** Always cache high-frequency command outputs at the top of Bash scripts. Use modern shell built-in regex matching instead of calling pipeline utilities (`grep`, `awk`, `sed`) to achieve maximum performance and stability.
