## 2026-07-26 - Optimized Process Forks in Zephyrus
**Learning:** The previous implementation of `zephyrus.sh` spawned multiple external command processes (`ps`, `grep`, `awk`) for each of the 25 Master Node checks. This resulted in over 150 process forks, causing high overhead. By caching the `kube-apiserver` command arguments in a global variable `KUBE_APISERVER_ARGS` at start and parsing them using pure Bash regular expression matching via `BASH_REMATCH`, we can eliminate all subprocess forks in the checks and perform the audit in pure Bash memory space.
**Action:** Always identify opportunities to cache command line outputs or process statistics once at the start of a shell audit script, and use native shell parsing arrays (`BASH_REMATCH` or pattern matching) instead of calling `grep` or `awk` in loops or multiple sequential functions.
