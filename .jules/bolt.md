## 2026-11-07 - Caching Process Arguments via Scoped Helper Function
**Learning:** In Kubernetes audit scripts like `zephyrus.sh`, querying `ps -ef | grep kube-apiserver` inside 25 distinct check functions creates massive subprocess fork overhead (~136 `execve` calls per audit run). Caching the process arguments string once at startup (`KUBE_APISERVER_ARGS=$(ps -ef | grep '[k]ube-apiserver')`) and providing a scoped helper `get_apiserver_args()` avoids globally monkey-patching `ps` while slashing fork overhead by ~58% (down to 56 forks) and cutting execution time by over 55%.
**Action:** When auditing static process configurations across many individual check functions, query and cache the target process arguments once at startup and pass them through downstream pipelines via a scoped accessor rather than re-forking `ps -ef` repeatedly.
